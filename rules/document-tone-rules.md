# 文体ルール（全資料共通の正本）

制定 2026-08-15。見出しと本文の文体を規定する**唯一の正本**。
スライド・提案書・記事・メール本文・議事録など、代表者名義で外部または社内に出る文章すべてに適用する。

各スキル（`pineal-slide-v2` / `pineal-slide-core` / `pineal-figure-v2` / `pineal-validate-v2` / `proposal-html` / `verify`）は、
このファイルを参照する。**規範文を各スキルに再掲してはならない**（再掲すると片側だけ更新されて矛盾する）。

**再掲禁止の唯一の例外**: `~/.claude/CLAUDE.md`。
このファイルは全セッションで自動ロードされる唯一の入口であり、
本正本を読む前の段階で効かせる必要があるため、要約を置いてよい。

置ける範囲は次に限る。

| 置いてよい | 置いてはならない |
|---|---|
| 「表記の共通ルール」の各項目の要約（**1項目につき1行**） | R1〜R7 の判定手順・型（F / N / R / S / P、A / B / C）・Fail 記号 |
| 本ファイルへのポインタ | 辞書1〜4 の語 |
| | 例外 E1〜E3 の条件 |

要約を置いた行には、本ファイルが正本である旨を併記する。
本正本と食い違った場合は本正本が優先する。

判定は必ず「例外 E1〜E3」→「R1〜R4（見出し）」→「R5〜R6（本文）」→「R7（命名）」の順に行う。

## 例外 E1〜E3（R1〜R4 の前に評価する）

| ID | 例外 | 短絡範囲 | 必要な証拠（列挙を**全て**満たす） |
|---|---|---|---|
| E1 | 顧客・製品の正式名称 | R1〜R4 | 公式資料での表記 **または** レビュー担当者の承認記録 |
| E2 | 改変禁止の引用・公式スローガン | R1〜R4 | 引用符 **かつ** 出典または承認記録 **かつ** 原文との完全一致 **かつ** 改変禁止である根拠（契約・ガイドライン・承認記録） |
| E3 | UI上の原文ラベル | R1・R2 のみ（R3・R4 は適用する） | 引用符 **かつ** 当該画面または公式ヘルプの参照 |

**優先順位**: E1 > E2 > E3。重複時は上位を適用する。

**適用範囲**: 見出し**全体**が保護対象と完全一致する場合のみ全体を短絡する。
一部だけが該当する場合は、**保護部分を記号1文字（◆）にマスクした元構文**に対して R1〜R4 を評価する。
文字列を削除してはならない（削除すると先頭が助詞断片になり構文が壊れる）。

例「Gemini Enterpriseで始める3つの未来」→ マスク後「◆で始める3つの未来」→ R1 Pass / R3 要確認 / R4 Pass → 確定は **R3 要確認**。

**証拠が揃わない場合**: 例外として扱わず通常判定にかける。証拠の有無はレポートの証拠欄に記録する。

**自作名称は E1 にならない**: 書き手（ピネアル側）が生成物の中で新造した名前・愛称は、
レビュー担当者または顧客の承認記録がない限り E1 の証拠を満たさない。
**生成物自身の中でその名前を使っている事実は証拠として認めない**（自己言及の循環になるため）。

**証拠は判定時の入力**: 出典・原文一致・改変禁止の根拠・公式表記は、判定者が成果物の外から与えられる前提情報である。
見出し文字列だけを渡されて証拠の有無が確認できない場合は、Pass にも Fail にもせず **要確認** とする。

## 見出しのルール R1〜R4

**判定対象**: h1 / h2 / h3 / h4、スライドタイトル、章題、記事見出し、カード見出し、表のヘッダー。
リード（`p.lead` / `.s-lead` / 本文冒頭）は**対象外**（結論はここに書くのが正しい）。

見出しは**全件を1件ずつ掃引する**。抜き取りは不可。

### R1 主題ラベルの原則

見出しには**主題を名指しする名詞句**を書く。結論を述べる文はリードに書く。

**判定手順（上から順に評価し、最初に該当した型で確定する）**

| 順 | 型 | 判定条件 | 結果 |
|---|---|---|---|
| 0 | **型P 工程ラベル前置** | 見出しが**工程ラベル**（下記の閉じた定義）で始まる | **Pass（R1 のみ短絡）** |
| 1 | **型F 有限節** | 見出し全体が述語で終わる（主語の明示有無を問わない）。**コピュラ省略型**を含む | **Fail（A）** |
| 2 | **型N 命題名詞句** | 主辞が**命題受け名詞**（辞書1）である。主辞の直前が節でも、サ変名詞＋「の」でも同じく型N | 直前部に**断定マーカー**（辞書2）があれば **Fail（B）**、なければ **Pass** |
| 3 | **型R 制限的連体節** | 主辞を節内の空所に戻せる | 節内に断定マーカーがあれば **Fail（C）**、なければ **Pass** |
| 4 | **型S 単純名詞句** | 上記いずれでもない | **Pass** |

上から順に確定するため型は一意に決まる。「実際に動かして分かったこと」は型R にも読めるが、順2 の型N で先に確定する。

**型P 工程ラベルの定義**（閉じた列挙。これ以外は型P にしない）

| 要素 | 許容する形 |
|---|---|
| 語（前置型） | `Step` / `STEP` / `ステップ` / `手順` / `Phase` / `フェーズ` / `Part`。**直後に数字を1つ取る** |
| 語（内包型） | `第N部` / `第N章` / `第N節`。**数字を語の内側に含むため、別の数字を続けない** |
| 数字 | 半角算用数字・全角算用数字・漢数字のいずれか1〜2桁。工程ラベル1つにつき1個 |
| 区切り | 全角コロン `：` / 半角コロン `:` / 全角読点 `、` / 半角ハイフン `-` のいずれか1文字 |
| 空白 | 語と数字のあいだ、区切りの前後に半角・全角空白0〜1個を許容 |
| 位置 | **見出しの先頭**にあること。文中・末尾の出現は型P にしない |

工程ラベルは**1つの見出しに1つだけ**。数字を2個持つ形（「第2部 2：…」「Step 2 3：…」）は型P にしない。
`第N部` の `N` がラベルの数字であり、それとは別の数字を続けた時点で工程ラベルの形から外れる。

型P は **R1 のみを短絡する**。R2・R3・R4 は引き続き評価する
（例「Step 2：やってみましょう」はラベル以降が呼びかけなので R2 で Fail）。

**コピュラ省略型**（型F に含める）: 末尾が名詞で終わっていても、次の3条件をすべて満たすものは型F。

1. 主題助詞「は」、または分裂文「〜のは」を含む
2. 末尾の名詞句に「だ／である」を補うと自然な文になる
3. 末尾の名詞句が見出しの**主辞ではなく述語相当**である（そのスライドの主題を名指ししていない）

「裏取りは人間の仕事」→ 3条件を満たすため型F Fail（A）。
「入力形式と出力形式」→ 条件1を満たさないため型S Pass。
「Gemini Enterprise の権限モデル」→ 条件1を満たさないため型S Pass。

**辞書1 命題受け名詞**（閉じた列挙。追加は本ファイルの改版で行う）

> こと、事実、結果、実績、成果、効果、理由、背景、経緯、点、状況、現状、課題、問題、傾向、意義、価値

**辞書2 断定マーカー**（閉じた列挙）

| 分類 | 語 |
|---|---|
| 数値 | 算用数字・漢数字を含む数量・割合・順位。**除外**: 年月日、時刻、所要時間、版番号、章番号 |
| 比較 | より、最も、一番、上回る、下回る、倍、分の、以上・以下（数値を伴う場合） |
| 成否判定 | 成功、失敗、有効、無効、不要、必要、最適、十分、不十分、可能、不可能、優位、劣位 |

**要確認**: 辞書1・辞書2 の境界で判断が割れる場合（語が辞書にないが同義と読める。例「確認済み」「効く」）は、Fail ではなく **要確認** とする。

**判定例**

| 見出し | 型 | 判定 |
|---|---|---|
| 保存する前に、その場で試せる | F | Fail（A） |
| 実際に動かして分かったこと | N | Pass |
| 実際に動かして分かった事実 | N | Pass |
| 内製化でコストが80%下がったこと | N | Fail（B） |
| コスト80%削減の実績 | N | Fail（B） |
| コスト削減の実績 | N | Pass |
| 回答品質を左右する指示文 | R | Pass |
| コスト削減手法 | S | Pass |
| コストが80%下がった手法 | R | Fail（C） |
| 参加者が作成するエージェント | R | Pass |
| 利用できるモデル | R | 要確認（「可能」の同義と読めるため辞書境界） |
| 9月に実施する研修 | R | Pass |
| 保存前のプレビュー | S | Pass |
| 指示文を貼り付けて生成する | F | Fail（A） |
| Step 2：指示文を貼り付けて生成する | P | Pass（R1 のみ短絡） |
| 裏取りは人間の仕事 | F | Fail（A。コピュラ省略型） |
| 差を作るのはロール文 | F | Fail（A。分裂文のコピュラ省略型） |

| 裏取りの担当 | S | Pass |

**修正の型**: 結論をリードへ移し、見出しにはその主題を名詞句で残す。
「同じ質問でも、指示文の詳しさで回答が変わる」→ 見出し「指示文の詳しさによる回答の違い」＋リード「同じ質問でも、返ってくる回答は次のように変わりました」。

### R2 発話行為の混入禁止

講師・書き手の行為宣言や読者への呼びかけを見出しに入れない。

**Fail条件**: 文末が「〜ます／〜ましょう／〜てください／〜しよう／〜みましょう」。

**例**: 「先に見せておきます」「実例で比べます」「回してみましょう」「見てください」

**修正の型**: リード文に移す。見出しには対象を名詞句で残す。

### R3 数え上げの禁止

箇条書きの個数を予告するだけの数字を見出しに入れない。

| 項目 | 内容 |
|---|---|
| **判定対象** | 数詞＋助数詞の形で、**直後の近接リストの個数を予告している**もの。近接リストが判定者に与えられていない場合は **要確認**（対象外と断定しない） |
| **対象外** | 個数予告でない数。所要時間（90分）、版番号（v2.1）、年月日、実測KPI、順序（1周目） |
| 件数一致＋外部根拠あり | **Pass**。版管理された手順書 ／ 正式なフレームワーク名 ／ 要求仕様・規格で定まった件数 |
| 件数一致＋根拠なし | **要確認**。証拠欄に「何を提示すれば Pass になるか」を書く |
| **件数不一致** | **Fail（構造整合性）**。見出しが「3ステップ」で本文が4項目、等 |

**生成側と検収側の非対称**: 生成側では**禁止**（外部根拠が手元にある場合のみ書いてよい）。検収側では成果物だけから便宜的分割を証明できないため Fail を出さず、根拠なしは要確認とする。

**例**: 「壁打ちで聞かれる7つの軸」（仕様に根拠）→ Pass。「導入の3ステップ」（本文3項目・根拠なし）→ 要確認。「導入の3ステップ」（本文4項目）→ Fail。「90分の流れ」→ 対象外。

### R4 修辞的装飾の禁止

**判定順（上から順に評価し、最初に該当したもので確定する）**

| 順 | 判定 | 条件 | 結果 |
|---|---|---|---|
| 1 | E2 | 改変禁止の引用・公式スローガン（証拠あり） | Pass |
| 2 | **型C 単独要素** | 比喩 ／ 読者への呼びかけ ／ 余韻止め（文末句点を伴う中断）のいずれか1つ | **Fail** |
| 3 | **「AからBへ」専用** | 「AからBへ」「AからBに」の形 | 外部証拠（承認済み用語集・既存プロセス図・正式名称）があれば **Pass**、なければ **要確認** |
| 4 | **型A 修辞的対称性** | ①2単位以上の同型構文 かつ ②対比・漸増・方向転換 かつ ③述語または助詞の省略（3要素すべて） | **Fail** |
| 5 | **型B 評価語の同型列挙** | 並列単位が評価語・副詞・形容詞であり、述語が省略されている | **Fail** |
| 6 | 上記いずれでもない | | Pass |

## 本文のルール R5〜R6

**判定対象**: 見出し以外のすべての文（リードを含む）。

### R5 擬人化・口語比喩・誇張の禁止

- **擬人化**: AIが「賢くなる」「学習して成長する」「同僚になる」「部下を持つ」
- **口語比喩**: 「時間を溶かす」「刺さる」「爆速」
- **誇張**: 「勝手に出来上がる」「〜だけで完成」「圧倒的」「劇的に」

**修正の型**: 観測できる事実に置き換える。「AIが学んで賢くなっていく」→「指示文を更新すると出力が変わる」。

**辞書5 AI臭検出語**（閉じた列挙。R5 の機械スキャン用。追加は本ファイルの改版で行う）

| 分類 | 語 | ヒット時の扱い |
|---|---|---|
| 空虚な強調 | 非常に、極めて、大幅に、飛躍的に、格段に | **Fail**（R5 誇張） |
| 定型の枕 | この度は、昨今、近年ますます、言うまでもなく | **Fail** |
| カタカナ盛り | ソリューション、シナジー、イノベーション、エコシステム、コミットメント | 要確認（製品名・正式名称の一部なら E1 で Pass） |
| 名詞句化 | 最適化、効率化、高度化、推進、実現、強化（述語なしで名詞のまま並ぶ場合） | 要確認（動詞に戻せるなら戻す） |
| 具体の省略 | 様々な、多様な（数えられる対象を数えていない場合） | 要確認（数えて書けるなら書く。本当に多岐にわたるなら Pass） |
| 自己美化 | 寄り添う、伴走する、真摯に、丁寧に | 要確認 |
| 断定回避 | と言えるでしょう、ではないでしょうか、ではないかと思います、と考えられます、と言われています、という声もあります、ということです、かもしれません（根拠の提示なしで。「かもしれません」は1段落に2回以上のときだけ） | 要確認 |
| 予告・締めの定型 | 今回は〜について紹介します、〜していきたいと思います、ぜひ〜してみてください | 要確認 |
| 強調の空転 | まさに（直後が特定の対象を指さず抽象語のとき） | 要確認 |

辞書5 は検出の入口であり、判定は文脈で行う。Fail 分類の語も、引用（E2）や顧客原文（E3）の中では短絡する。
接続詞（また、さらに、加えて）が1段落に3回以上続く場合、および受動態・「〜という点において」型の抽象化が続く場合も R5 の要確認に含める。

**「まさに」の判定**: 直後が特定の対象を指すなら Pass（「現場が求めていたのは、まさにこの粒度の手順書でした」）。
直後が抽象語なら要確認（「生成AIの活用は、まさに経営課題です」）。

**予告・締めの定型の修正の型**: 予告は本題そのものに置き換える。
「今回は研修の設計方針について紹介します」→「研修の設計方針を、業務標準書との接続という一点に絞って書きます」。
締めは相手・期限・成果物を書く。「ぜひ現場の声を聞かせてみてください」→「現場の反応を、11月の定例までに一次情報でください」。
見出しの「〜てください」は R2 で Fail であり、本文でこの項の要確認に当たる。

**機械検出との分担**: 辞書5 のうち断定回避・予告・締めの定型・具体の省略の各語は、
`~/.claude/skills/japanese-tech-writing/scripts/njlint.sh` では検出できない（実測でゼロヒット）。
機械スキャンに任せず、必ず人手で当てる。

### R6 読者の感情を決めつけない

読み手がどう感じるかを書き手が断定しない。

**例**: 「たぶんがっかりします」「驚くはずです」「安心していただけます」「ワクワクする」

**修正の型**: 事実だけを書き、感情の記述を削る。

## 命名のルール R7

**判定対象**: 生成物の中で機能・画面・仕組み・成果物・提案概念に与える**名前**。
見出し・本文・図ラベル・キャプション・凡例のすべてで判定する。
名前を含む見出し・文は R1〜R6 の判定も通常どおり受ける（R7 の Pass は他ルールを短絡しない）。

### R7 比喩ネーミングの禁止

名前は、対象の**種別と役割が分かる記述的な語**で構成する
（例: 営業支援アプリ、顧客×商材マトリクス画面、送信前プレビュー）。
道具・場所・人物役割・情景になぞらえた愛称（比喩ネーミング）を付けない。

**判定手順（上から順に評価し、最初に該当した項で確定する）**

| 順 | 判定 | 条件 | 結果 |
|---|---|---|---|
| 1 | E1 | 顧客・製品の正式名称（証拠あり。E1 の「自作名称は E1 にならない」を適用） | Pass |
| 2 | 定着技術語 | 比喩と読める語が辞書3 または辞書4 にある | Pass |
| 3 | 比喩ネーミング | 名前が、道具・場所・人物役割・情景になぞらえた語を含む | **Fail** |
| 4 | 記述的命名 | 上記いずれでもない | Pass |

**辞書4 命名判定で定着技術語として扱う語**（閉じた列挙。辞書3 への追加ではなく R7 専用。追加は本ファイルの改版で行う）

## 表記の共通ルール

- 文章でダッシュ（──・—・–）を使わない。句読点・コロン・読点で代替する
- 正式社名は「**株式会社ピネアル**」（前株）。「ピネアル株式会社」は誤記
- 丸括弧の補足を多用しない。1文に2つ以上、または1段落に3つ以上の丸括弧補足があれば、補足を独立した文か下位の箇条書きに出す（引用元・型番・正式名称の併記は対象外）
- 箇条書きはトップレベルを短い項目ラベル、詳細・補足・数値を1段下げて書く。マーカーは Markdown の `-`（HTML では `<ul>`）に統一し、全角中黒「・」を行頭マーカーに使わない
- 表のセルには2文以上を流し込まない。2文以上になるならセル内を箇条書きに分解するか、行を分ける
- 表のヘッダー行に空の列名を置かない。行見出し列にも列名を付ける（例: 観点、項目、区分）
- 数字は淡々と扱う。**上から順に評価し、最初に該当した項で確定する**。
  1. **対象外（短絡）**: 次のいずれかに当たる数値は、以降の項を評価しない
     - 図表が図形の長さ・面積・位置・段の並びで表す量に付ける注記
       （棒グラフ・バブル・ファネル・比較バー等のラベル。級数は問わない）
     - 工程番号、章番号・節番号、連番、年月日、時刻、所要時間、版番号
     - 本文・見出し・表のセル・箇条書きの項目の中に、文の一部として現れる数値
  2. **数値カードを使わない**: 1 に当たらない数値のうち、数値（と短い単位・ラベル）だけを内容とする要素に置き、
     その数値の級数が**基準本文級数**の2倍以上になるもの
  3. **複数の数値を並べて示すとき**は箇条書きまたは表にする
  - **基準本文級数**は、その資料が従う正本が判定用に定める単一の本文級数を指す。
    v2 系統は `pineal-slide-v2/references/style-guide.md`「タイポグラフィ」の本文、
    proposal 系統は `proposal-html/SKILL.md`「基準本文級数」の表（モード別）。
    テンプレート CSS の継承値でも、密度上限表の最小値でもなく、この値で測る
  - 派生スキルはこの規則を再掲せず、どのコンポーネントがこれに当たるか（legacy 扱いを含む）だけを持つ
- 「体言止め」という語は**使わない**。同じ語が「主題ラベル（可）」と「標語型（不可）」の両方を指してしまうため、R1 の型（F / N / R / S）と R4 の型（A / B / C）で呼び分ける

## 検収レポートの様式

`/verify` はこの正本に照らした結果を次の3区分で出力する。

- **見出し**: 総数、R1〜R4 ごとの違反数、全件の判定表（見出し文言 / 判定 / 該当 Rule・型 / 例外ID / **証拠**）
- **本文**: 走査範囲、R5・R6 ごとの違反箇所一覧
- **命名**: 生成物内で新造された名前の一覧と、R7 の判定（Fail・要確認の該当箇所つき）
- **要確認**: R3・R4・R7 の根拠不明分。各件に「何を提示すれば Pass になるか」を書く

**総合判定**: 未解消の要確認が1件でもあれば Pass にせず **要確認** とする。
