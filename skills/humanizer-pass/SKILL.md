# humanizer-pass

公開前の文章を、留保、段落のつなぎ、語の選び方の観点で部分修正する工程。
humanize と gemini-rewrite の後、機械チェックと人の通読の前に置く。

## 前提

- 優先順位
  - ルールと媒体の規則が食い違ったら媒体の規則に従う
  - 媒体の規則は `~/.claude/rules/document-tone-rules.md` と、媒体ごとの文体ガイド
- 目標にしないもの
  - 検出器の点数、文長のばらつき、同じ文末の回数
  - 不規則な文や誤りを加える修正はしない
- この工程で増えないもの
  - 書き手の経験、動機、判断の理由
  - 足りないときは書き手に確認する。推敲で作らない

## ルール本文の扱い

- このスキルにも各リポジトリにも保存しない
  - 配布元にライセンスの記載がないため
  - 実行のたびに取得し、作業フォルダにだけ置く
- このスキルの派生版を公開するときも、長い引用や近い言い換えを入れない

## 対象

| 文書 | 扱い |
|---|---|
| コラム、技術記事、note | 2周回す |
| 提案書の地の文 | 試行として回し、節ごとに人が採否を決める |
| スライド、定型の企画書、X の配信パッケージ | 全文には回さない |

## 手順

1. 作業フォルダを scratchpad に作り、対象を `r0.md` へコピーする
2. ルールを取得する

   ```bash
   bash ~/.claude/skills/humanizer-pass/scripts/fetch-rules.sh <作業フォルダ>/humanizer.ja.txt
   ```

   - 終了コード0は確認済みの版、1は取得失敗、2は版違い
   - 版違いのときは、前の版との差分を読んでから使い、同スクリプトの既知ハッシュ、バイト数、日付を更新する
3. 1周目: sonnet の subagent に `r0.md` から `r1.md` を作らせる
4. 差分を検査する

   ```bash
   python3 ~/.claude/skills/humanizer-pass/scripts/guard.py r0.md r1.md --protect-after "<CTA の冒頭文>"
   ```

   - 終了コード1の変更は戻す
   - CTA のない文書は `--protect-after` を省く
5. 2周目: 1周目とは別の sonnet の subagent に `r1.md` から `r2.md` を作らせる
6. 手順4と同じ検査を `r1.md` と `r2.md` に行う
7. 親が `r0.md` と `r2.md` の差分を全部読み、採否を決める
   - guard.py は主張の強さ、帰属、留保の変化を見ていない。この3点は親が読む
   - 改善を説明できない変更は戻す
8. 採用した版を元のファイルへ反映し、各工程の手順書が指定する場所へ記録を残す
   - 取得日、バイト数、sha256、周ごとの変更箇所数、戻した変更

2周目で直す箇所がなければ、そこで終える。3周目は回さない。

## subagent への指示

共通部分の波括弧を埋め、「この周の進め方」に周ごとの文を入れて渡す。

```markdown
あなたは日本語文書の推敲担当です。ルールファイルを全行読み、文書の地の文へ当てて、必要な箇所だけを直してください。

## ファイル
- ルール: {作業フォルダ}/humanizer.ja.txt
- 入力(変更しない): {前の版}
- 出力: {この周の版}。先に cp で入力を複製し、Edit で部分修正する。全文を書き直さない
- 媒体の規則: {媒体の規則のパス}。ルールと食い違うときはこちらを優先する
- Bash でファイルを読むときは cd を使わず絶対パスで行う

## 文書
{媒体、読者、用途を2文で}

## この周の進め方
{周ごとの文}

各変更は、正確さ、自然さ、読み取りやすさのどれをどう改善したか説明できるものだけ残します。語尾を変えるためだけの変更はしません。直す箇所がなければ、その節は変えません。

## 守ること
- 事実を足さない。固有名詞、数値、日付、URLを変えない
- 主張の対象、条件、出所、強さを動かさない。帰属と留保の意味を残す。伝聞を断定にしない
- 体験や感想を作らない。検出器の点数を目標にしない。不規則な文や誤りを加えない
- 全体の長さを増やさない
- {冒頭に残す語、言い換えない用語など、文書固有の条件}

## 変更しない範囲
- frontmatter 全体と見出し
- コメントとリンクカードの行
- 図の行とキャプション、表の行、`<img>` タグ、リンクのURL
- {引用の囲み、CTA など、媒体固有の範囲}

## 報告
400字以内で返してください。
- 直した類型を3〜5個(各類型の件数つき)
- 残すか迷った箇所を1〜2個
- 意味が動くと判断して止めた箇所があれば1個
```

1周目の「この周の進め方」:

```markdown
ルール末尾の「執筆後の確認事項」1〜6を順に、地の文の全段落へ当ててください。次の節は1段落ずつ照らします。
- 「留保と適用条件」: 別の箇所と同じ留保、範囲を主張に含めれば消せる注意文
- 「段落のつなぎ方」: 案内だけの文、図表の読み方を述べるだけの文
- 「文末の意味と文型の反復」「列挙」: 述語が文の役割に合うか、同じ対応関係の述語が不要に変わっていないか
- 「語彙の選び方」: 抽象的な動詞、作業用の語、耳慣れない語の組み合わせ
- 「文の構造」の表: 迂回表現、指示語、主述
```

2周目の「この周の進め方」:

```markdown
「執筆後の確認事項」のうち次の3点を中心にしてください。1周目の入力は {r0.md のパス} です。
- 2 構成と重複: 節の境目を前後続けて読み、話題の変わり目で関係を追えるか確かめる
- 4 文と語句: 日本語の文章として通読し、読者が前の文へ戻る箇所がないか確かめる
- 5 比較と採否: 1周目の入力と比べ、悪化した変更や改善を説明できない変更が残っていれば戻す

直す箇所が少なければ少ないまま終えてください。
```

## 根拠と限界

- 2026-11-02 にコラム1本へ3周当てた結果
  - 変更箇所は2、4、1で、全項目を全段落へ当てた周が最多、通読の周で収束した
  - 事実と主張の強さは動かなかった
- 2周の手順は、この結果から周の内容を組み直したもので、この順序での通し実行はしていない
- 記事1本の結果で、対照がない。初稿と提案書には当てていない
