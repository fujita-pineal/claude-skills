# 図版設計ガイド(パイプラインv3)

図版計画は Stage 1(ブリーフ設計・fable)で決め、作図は Stage 4(opus)が行う。本書はその両方の判断基準。

前提として、**図は記事を飾るものではなく、文章では読者の作業記憶に載らない情報を肩代わりするもの**。この基準を外れた図は、認知負荷を下げるどころか増やす。

## 1. 図を入れるか入れないか

### 入れる

- **3つ以上の要素の関係**を説明している(包含・重なり・対立・依存)
- **順序と分岐**がある(手順、判断フロー、承認経路)
- **2軸以上の比較**をしている(表に並べても差が見えないもの)
- **実測データ**がある(自社GSC、案件の改善数値)
- **実際の画面**を見せないと手が動かない(How-to記事の操作説明)

### 入れない

- 箇条書きを四角で囲み直しただけ
- 文章1〜2文で足りる内容
- 「なんとなく図があった方がそれっぽい」という理由
- **図にすると嘘になる場合**。実測値がないのにグラフを描く、実案件でやっていない工程をフローに含める

### 点数の目安

| 記事タイプ | 目安 |
|---|---|
| ピラー記事(カテゴリの核) | 2〜4点 |
| 個別記事 | 0〜2点 |

**0点も正解**。ブリーフに「図版なし」と理由を書けばよい。ノルマではない。

## 2. 図種カタログ

| 図種 | 解決する問題 | 形式 | 主な記事タイプ |
|---|---|---|---|
| **概念マップ** | 用語同士の位置関係。「AとBの違い」を文章で書くと往復が増える | SVG | 「〜とは」系 |
| **業務フロー(BPMN)** | 誰が・どの順で・どこで分岐するか。担当者が複数いる運用フロー | drawio | 導入・運用系 |
| **手順ステップ図** | 直線的な手順の全体像。分岐がなくレーンも不要な場合 | SVG | How-to |
| **比較マトリクス** | 選択肢を2軸に配置する。表では「どれが自分向きか」が分からないとき | SVG | 比較・選定 |
| **システム構成図** | ツール間のデータの流れと連携点 | drawio | MA/CRM、データ分析 |
| **Before/After** | 変更の前後を並置する | SVG | 事例、改善 |
| **時系列・ロードマップ** | 段階導入の期間感と順序 | SVG | 戦略 |
| **データ可視化** | 実測値の大小・推移。**実測値がある場合のみ** | SVG | 一次情報型 |
| **操作スクリーンショット** | 実際のUIを見ないと再現できない手順 | webp | How-to |

### SVGかdrawioか

**drawioを使う**のは次のいずれかに当てはまるとき。

- プール/レーンで担当を分ける(BPMN)
- ノードが10個を超える、または分岐が3本以上ある
- 後から要素を足す前提がある(座標を手で直すのが破綻する)

**それ以外はSVG直書き**。drawioはソースが冗長になるので、単純な図に使うと差分レビューが読めなくなる。

## 3. BPMN の書き方

読者はBPMNの専門家ではない。**使う記号を5種類に絞る**。

| 記号 | 意味 | 見た目 |
|---|---|---|
| プール/レーン | 誰がやるか(例: 事業部 / マーケ部 / 外部パートナー) | 横帯 |
| 開始・終了イベント | フローの入口と出口 | 細い円 / 太い円 |
| タスク | 実行する作業 | 角丸四角 |
| 排他ゲートウェイ | 択一の分岐 | ひし形。分岐条件を必ずラベルに書く |
| シーケンスフロー | 順序 | 実線矢印 |

**使わない**: 中間イベント、並列ゲートウェイ、サブプロセス、データオブジェクト、メッセージフロー。これらが必要なほど複雑なフローは、記事に載せる粒度としてそもそも細かすぎる。分割するか、抽象度を上げる。

### BPMN図の作り方

**レーンは縦割りにして、流れを下向きに書く。** BPMNは横に流すのが通例だが、コラム本文の表示幅は740px前後しかない。ノードが8個ある横フローは書き出し幅が1600近くなり、記事幅に縮めると16pxの文字が実効7px相当まで潰れる。レーンを縦の列にして流れを下向きにすれば幅1000前後に収まり、実効11px前後を保てる。

**drawioソースの作法**(外すと壊れる):

- スタイルは `html=0`。`html=1` だとラベルが `foreignObject` + base64 PNG で書き出される。`<img>` で読み込むSVGでは `foreignObject` が描画されずPNG側が使われるため、文字がラスタになって拡大でぼやけ、ファイルも肥大する(実測 195KB → 9KB)
- `whiteSpace=wrap` を使わない。これも `foreignObject` 経路に落ちる。改行は値の中に `&#10;` を直接書く
- 日本語フォントは `fontFamily=Hiragino Sans` で統一する。エクスポートスクリプトがフォールバック鎖に展開する

1. `docs/seo-column/figures/{slug}/fig-N.drawio` にソースを書く
2. エクスポート:
   ```bash
   scripts/drawio-export.sh {slug} N
   ```
   drawio CLIのSVG出力は**背景が透過**になり、そのままではダークモードで濃い線が濃い背景に乗って読めなくなる。加えて29系は全色を `light-dark(明, 暗)` で書き出すため、白背景で固定した図にダークモード側の淡色が乗って線と文字が飛ぶ(`--svg-theme light` では消えない)。このスクリプトが余白付きでエクスポートしたうえで白背景の注入・`light-dark()` の明側への畳み込み・フォント鎖の展開をまとめて行い、`foreignObject` が残っていればエラーで止める。`drawio --export` を直接叩かないこと
3. **エクスポート後のSVGを必ずブラウザで開いて目視確認する**。日本語のフォント幅で文字が枠からはみ出す事故が起きやすい

## 4. デザイン規約

サイトのトークンは `src/styles/tokens.css`。

### 配色

| 用途 | 色 |
|---|---|
| ブランドアクセント | `#d21e2d`(赤) |
| ベース(枠線・文字) | `#1a1a1a` 〜 `#666` のグレースケール |
| 面(強調) | `#1a1f4d` 系の紺 |
| 面(補助) | `#f4f5f7` 〜 `#e8ecf4` の淡色 |

**ブランド赤は1図あたり1〜2箇所まで**。「ここを見てほしい」1点に使う。全体を赤くすると強調が消える。

### フォント

```
font-family="'Noto Sans JP', 'Hiragino Sans', 'Yu Gothic', sans-serif"
```

図版は `<img>` で読み込まれるためサイトのWebフォントが効かない。**必ずシステムフォントへのフォールバックを書く**。閲覧環境によって字幅が変わるので、テキストは枠にぎりぎりで詰めず余白を持たせる。

### サイズ

- viewBox の幅は **1200** に固定。高さは内容に応じて可変
- 図内の最小文字サイズは **viewBox上で16**(記事幅で表示すると実効12px程度)
- 記事ページ側で `border-radius` が自動で付く(`.body :global(img)`)

### 背景

**白ベタで固定する**(`<rect width="1200" height="H" fill="#ffffff"/>` を最初に置く)。ダークモードでも白いカードとして成立する。SVG内でダークモード切替を実装しない — `<img>` 読み込み時の挙動が環境で割れるうえ、メンテナンス対象が増える。

### 作図時の落とし穴

前回のHTML資料で実際に踏んだもの。

- **`<text>` の中に `<br/>` を書かない**。HTMLパーサーがSVGを打ち切り、以降が壊れる。改行は `<text>` を分けるか `<tspan>` を使う
- **`class` と `fill` 属性を併用しない**。CSSルールが presentation attribute に勝つので、`class="x" fill="white"` の白は効かない。インラインの `style="fill:#fff"` を使う
- **`text-anchor` の既定を確認する**。クラスで `middle` を当てていると、左揃えのつもりの `x` 座標が中央基準になり文字が枠外へ出る
- **図の最下部に要素を置くときは viewBox の高さに余裕を持たせる**。ベースライン基準なので下端ぴったりだと descender が切れる
- **矢印マーカーは右向きに定義して `orient="auto"` を使う**(`M 0 0 L 10 5 L 0 10 z` / `refX="9" refY="5"`)。上向きのパスを書いて `orient="auto-start-reverse"` にすると、反転が効くのは `marker-start` だけなので `marker-end` の矢印が真横を向く
- **描き終わったら余白を詰める**。要素の下端と viewBox 下端が離れていると、記事内で図の下に不自然な空白が入る

## 5. 文章との役割分担

図を入れたら、**本文で図の内容を繰り返さない**。

- 悪い例: フロー図を置いた直後に、同じ手順を箇条書きでもう一度並べる
- 良い例: 図で全体像を示し、本文では図に書けない「なぜその順序なのか」「どこで詰まりやすいか」を書く

図の要点は**キャプション1行**で拾う。SVG内の文字は検索エンジンに読まれないので、図だけに情報を置くとその内容は検索面から消える。

```markdown
[![承認フローの分岐を示すBPMN図。マーケ部が起案し、法務チェックで差し戻しが発生する経路がある](/images/column/ad-compliance-guide/fig-2.svg)](/images/column/ad-compliance-guide/fig-2.svg)

*図2: 広告表現の承認フロー。差し戻しの多くは法務チェックではなく起案時の根拠資料の不足で起きる*
```

キャプションは図の説明ではなく、**図から読み取ってほしい結論**を書く。

画像は**自分自身へのリンクで包む**。viewBox幅1200の図はモバイル(実表示342px)では文字が5px相当まで縮むので、タップでSVG単体を開けるようにしてブラウザのズームに逃がす。サイト側のCSS改修は不要。
