# gemini-rewrite

Claude が内容を固めたものを、Gemini に書き直させる。判断や事実の追加は Gemini に任せない。

書き手モデルと校閲モデルを分けるのが要点。同じモデルに書かせて同じモデルに直させると、自分の文体を自分で許してしまう。
別のモデルが書き、元のモデルが原文との差だけを見る方が、文体は変わり意味は残る。

## まず決めること: 全面書き直しか、最小改稿か

モードの違いより先に、原文がどちらに当たるかを決める。

| 原文の状態 | 頼み方 | 使うもの |
|---|---|---|
| Claude が組み立てた下書き。文としてはまだ荒い | 全面書き直し | 平文モード、記事モードの `standard` |
| すでに人が書いて形になっている。直したいのは読みにくい箇所だけ | 最小改稿 | 参照ページモード、`gemini_rewrite.py --minimal` |

**形になっている文に全面書き直しを頼むと、壊れていない文まで書き換わる。**
社内向け参照サイトの12ページへ「自然な日本語へ書き直す」で当てたところ、
敬体化、漢語への置き換え、原文にない丸括弧の補足が全ページで出て、採用できたのは一部だけだった。
同じ12ページに「読んで引っかかる箇所だけ直す。引っかからない文は1文字も変えない」で当て直すと、
変更は1ページあたり1〜6片に落ち、全ページが機械検査を一発で通り、全件をそのまま採用できた。
さらに、採用後のページへもう一度当てると変更は0片になる。直し終えた文はもう触らない。

指示に入れる文体の制約は次の4つ。全モードに入っている。
これが無いと、Gemini は「読みやすくする」を「硬く整える」と解釈し、出力を採用できなくなる。

- 文末の丁寧さを行ごとに原文のまま保つ。常体の行を「です・ます」に変えない
- 原文にない丸括弧の補足を足さない
- 和語を漢語に置き換えない（「作る道具」→「作成ツール」、「止める」→「制限する」）
- 中黒「・」を語の並列に使わない

## 平文モード(メール・チャット返信)

1. Claude 側で内容(伝える順序、判断、要望)を確定した下書きを作る
2. 実行
   ```
   printf '%s' "$DRAFT" | python3 scripts/gemini_rewrite.py --persona "〇〇社のCTO" --brief "宛先は〇〇さん、8行以内、口調はやわらかめ"
   ```
   - `--persona` は書き手の立場。省くと「この文章の書き手本人」になる。`GEMINI_REWRITE_PERSONA` でも渡せる
   - 社名の表記など、書き手固有の決まりは `--brief` に書く
   - すでに形になっている文を渡すときは `--minimal` を付ける(全面書き直しをやめ、引っかかる箇所だけ直す)
3. 出力を `rules/document-tone-rules.md` の R5(辞書5)と表記ルールで目視確認し、直した語があれば1行で報告する
4. ユーザーにはコードブロックで本文だけ出す

## 参照ページモード(HTML断片の最小改稿)

サイトの本文を HTML 断片で持っている場合に使う(`pages/*.html` など)。
短い常体の箇条書きと表でできた参照ページが対象で、読み物ではない。

```
python3 scripts/html_rewrite.py <pages ディレクトリ> <outdir> [--files a.html,b.html] [--brief "このサイトの事情"]
```

- 1ページ1リクエスト。機械検査に当て、違反があればその箇所だけを直させる差し戻しを2巡まで回す(`--rounds`)
- 機械検査: タグ列の完全一致、`pre`/`code` の中身、数値の多重集合、`href`、禁止語、
  タグを境にした片ごとの常体→敬体・丸括弧の増加・中黒の増加・1.2倍超の伸び、全体の字数 ±15%
- 記事モードと違い、校閲モデルの照合は使わない。断片が短く、片ごとの機械検査で足りる
- 出力は `<outdir>/` に同じファイル名で並ぶ。**適用は Claude が行う**。全ページの diff を読んでから当てる
- 変更片数が1ページで2桁になったら、指示が緩んでいるか原文が荒れている。採用する前に止めて中身を見る

## 記事モード(Markdown 記事のループ書き換え)

公開済みまたは執筆済みの Markdown 記事を、意味を変えずに「人が書いた自然な文」へ寄せる。
下の調整は gemini-3.8-flash で実測したもので、Gemini 4 では測り直していない。
用語集と校閲モデルの照合が今も要るかは未検証。回す前提は変えずに使う。

```
python3 scripts/article_loop.py content/foo.md /tmp/out --rounds 3
```

- 仕組み: 最初に校閲モデル(既定は Claude の sonnet)が記事全体から用語集を抽出する。次に frontmatter を外し、コードフェンス外の h2 で節に分割。節ごとに Gemini 書き換え → 機械チェック + 校閲モデルの意味照合 → 指摘を Gemini に戻して再書き換え。指摘ゼロか rounds 到達で確定
- 校閲モデルの呼び方は `--checker` で選ぶ。既定は `agent`(`claude -p` を使わない)
  - `agent`: スクリプトは照合用プロンプトを `<outdir>/checks/` に書き出し、終了コード 3 で止まる。表示された指示文を1件ずつ Agent ツール(`model: sonnet`、general-purpose)に並列で渡し、全件の JSON がそろったら表示された同じコマンドを再実行する。終了コード 0 と「完了」が出るまで繰り返す(用語集で1回、巡回ごとに1回止まる)
  - 指示文は書き換えずにそのまま渡す。subagent に照合の基準を足したり、呼び出し元が代わりに判定したりしない
  - subagent は同じ照合指示でも「迷ったら書かない」に強く従い、A〜C の1語差を落としやすいため、agent モードだけ「1文ずつ対応させ、迷ったら fact_changed を付けて入れる」補足を足している(5節で比較: 事実が変わる指摘は `claude -p` 8件、補足なし subagent 9件、補足つき 13件)
  - `cli`: 校閲コマンドで照合し、止まらずに最後まで進む。Claude Code の外から回すとき用。`GEMINI_REWRITE_CHECKER=cli` でも切り替えられる
    - 校閲コマンドの既定は `claude -p --model sonnet`。`REWRITE_CHECKER_CMD` で別のモデルやコマンドに差し替えられる
    - 差し替えるコマンドは、stdin にプロンプトを受け取り、JSON を stdout に返す。照合では `{"issues":[...]}`、用語集の抽出では `{"terms":[...]}`
  - 途中で照合方式を変えると別の途中結果として扱うため、outdir を分ける
- 機械チェック: 見出し・コード・表・画像行・HTMLコメントの完全一致、数値とリンクURLの多重集合一致、用語集の語の出現回数が減っていないか、禁止語、丸括弧と中黒が原文より増えていないか、漢語の増加、「のです。」の増加、文末の連続、文字数 ±25%
  - 漢語の増加: 地の文の漢字の比率が2ポイント以上増えたら、原文にない漢字2字以上の語を挙げて差し戻す。漢語化は適用時に戻すのでなく、ループの中で直させる
  - 「のです。」の増加: 原文より2個以上増えたら差し戻す。文末の反復を避けさせると、Gemini は語尾に「のです」を足してずらす(実測: 1巡目で 0個→6個)
  - 文末の連続: 同じ文末(「。」の直前2文字)が3文以上続く箇所が、原文の半分以下になるまで箇所を渡して組み替えさせる。指示だけでは減らない回がある(実測: ある記事で 9件→9件)
  - 禁止語は `--banned words.json`(JSON 配列)で差し替えられる
- `standard` の指示は、文の組み立ては自由に変えさせ、語彙と文末は原文に揃えさせる。あわせて、同じ文末が3文続く箇所を組み替えさせる
  - 否定からの対比を組み替えさせる指示は外した。照合役が「対比が落ちた」を事実の欠落として差し戻すため
- 用語集: 節単位の照合では記事全体の用語のずれが見えないため、用語集を Gemini への指示と機械チェックの両方に使う。抽出結果は `<outdir>/glossary.txt`。`--glossary <file>`(1行1語)で差し替え、`--glossary none` で無効
  - 入れるのは製品名、制度の名称、定着した専門用語だけ。書き手の造語を入れると言い換えから守られ、違和感のある語が最後まで残る(造語が全工程を素通りした実例がある)。実行前に `glossary.txt` を読み、造語を消す
- 意味照合は「実害のある問題だけ」を指摘する緩い設定。語彙や語尾の差は指摘しない(厳しくすると原文に引き戻されて変化が小さくなる。実測)
  - ただし断定の強まり、主体・関係の変化、限定の語の消失の3つは、語尾や助詞1語の差でも指摘する(緩い設定のままだと、公開済み3本で事実の強さが変わる書き換えが素通りした)
  - 照合役が `fact_changed: false` を付けた指摘(表現の差だけ)は差し戻さない
  - 差し戻しでは「前回の書き換えを土台に、指摘箇所だけ直す」と指示する。「原文に戻す」とだけ書くと節全体が原文へ引き戻される(実測: 原文との一致率 0.84 → 0.96)
- `cli` で校閲コマンドが失敗したとき(未ログイン、タイムアウト、JSON で返らない)は1回再試行し、駄目なら中断する。エラー文を指摘として Gemini に戻さない
- `agent` で subagent の JSON が読めないときは、スクリプトが該当ファイル名を出して止まる。そのファイルを消して、その1件だけ subagent をやり直す
- `--tone casual` で口調を「ほんの少しだけカジュアル」にする(SNS の長文記事・個人ブログ向け)。原文の文をベースに語尾と接続だけ崩す最小書き換え
  - 既定の `standard` は原文から離れて書き直すため、常体混じり・口語の原文は丁寧・硬い方向へ戻る(「作ってません」→「作っていません」)。くだけた原文に既定を当てない(実測)
  - frontmatter のない Markdown もそのまま渡せる
- `--sections 2,3` で節番号を絞れる(0 は導入)。`--model` / `GEMINI_REWRITE_MODEL` でモデル変更
- 出力: `<outdir>/final.md` が完成形。`s{NN}-r{N}-issues.json` で残った指摘を確認する
- 適用は下の「記事モードの適用: 採用が既定」に従う
- `--tone casual` の出力も採用が既定。戻すのは次の型に当たる片だけ
  - 採用の例: 語尾の軽い崩し(「〜しています」→「〜してます」、「〜です」→「〜なんです」)、硬い語の言い換え(「一組にした」→「セットにした」)、軽い「正直」「そのまま」
  - 「んですよね」は記事全体で2か所まで。Gemini は段落ごとに足すので、超えた分は原文に戻す
  - 箇条書きの体言止め・常体に「です・ます」が付いたら戻す(丁寧化になる)
  - 冒頭1文目のくだけ(「〜流れてきたんですよね」)、日本語として座りの悪い語順(「ちょっと1段落だけ」)、原文にない動作の宣言(「書いてみます」)は戻す

### 記事モードの適用: 採用が既定

Gemini の案は全部採用し、決まった理由に当たる片だけを原文に戻す。

以前は diff を1か所ずつ見て採否を選んでいた。記事7本へ当てたときは、採用が文の分割と読点の整理だけに縮んだ。
戻した理由は「Gemini の出力は漢語が増えて硬くなる」だった。いまは生成側の指示と機械チェックで漢語化を止めている。

```
python3 scripts/adopt.py list <原文.md> <outdir>/final.md
python3 scripts/adopt.py apply <原文.md> <outdir>/final.md <書き出し先.md> --revert 3:fact,7:tone
```

- `list` は変更片(文か改行で区切った差分のかたまり)に番号を振り、原文にない漢語と辞書5の語をヒントに付ける
- `apply` は指定した片だけ原文に戻し、残りを採用して書き出す。空行だけの差は数えず、原文の改行を残す
- 戻す理由は次の5つだけ。スクリプトはほかの理由を受け付けない

| 理由 | 当たるもの |
|---|---|
| `fact` | 照合で残った `fact_changed` の指摘。数値、固有名詞、限定の語、用語の定義が動いた片 |
| `dict5` | 辞書5の Fail 語、ダッシュ、擬人化、読者感情の決めつけが入った片 |
| `tone` | 文末の丁寧さ(敬体と常体)か一人称が原文から変わった片 |
| `kango` | 漢語に置き換わり、語を1つ戻しても文が硬いままの片 |
| `keep` | 守る段落。引用、顧客の原文、CTA、連載案内、見出し |

- 戻さない理由
  - 原文の言い回しの方が好き、書き手の声が薄まる、変更が多い
  - 迷ったら採用する
- 語だけおかしい片は、片ごと戻さない。採用してから、その語だけ手で直す(漢語1語を和語に戻す、など)
- 残指摘は節ごとに戻さず、指摘の当たる片だけ戻す
- 報告には `apply` が出す採用率と、戻した理由の内訳を載せる
- 適用後に、同じ文末が3文以上続く箇所を数え、原文と比べる(数え方は `article_loop.py` の `end_runs` と同じ)。増えていたら該当の片を見直す
- 実測(記事2本、gemini-4-argon、照合は `cli`)
  - 地の文の漢字の比率(照合前の1巡目): 記事A は原文 28.5%、旧指示 32.6%、新指示 28.8%。記事B は 28.4%、29.7%、27.9%
  - ループを通した採用率: 記事A は 22片中22片(常体になった1語だけ手で直した)、記事B は 21片中20片。戻した1片は、手順の説明が仕組みの説明に変わった `fact`
  - 同じ文末が3文以上続く箇所(採用後): 記事A は 10件から5件、記事B は 9件から4件

### 記事モードの後処理

- 一文一行の記事は、適用後に `。` で改行を戻す(コード・表・箇条書き・インデント行は触らない)
- 記事側の機械チェック(リンク、frontmatter、レビューゲート等)は適用後に通す

## 前提

- `GEMINI_API_KEY` を環境変数に入れておく。依存ライブラリなし(標準ライブラリで REST API を叩く)
- 既定モデルは `gemini-4-argon`(gemini-3.8-flash から変更)
  - Gemini 4 は Hydrogen(速い・安い)、Argon(汎用)、Carbon(最上位・遅い)の3種。書き直しには Argon を使う
  - 単価は Argon が 3.8-flash より高い。大量に回すときは `--model gemini-4-hydrogen` を試す
- 記事モードは Claude Code のセッションから回す前提(照合を subagent に任せるため)。`claude -p` のログインは要らない
  - Claude Code の外から回すときは `--checker cli` を使う。校閲モデルは `REWRITE_CHECKER_CMD` で差し替えられる
- スクリプトは4本。`gemini_rewrite.py`(平文、`--minimal` 付き)、`html_rewrite.py`(参照ページ)、`article_loop.py`(記事)、`adopt.py`(記事モードの適用)
- 参照ページモードの実測(社内向け参照サイトの12ページ、gemini-4-argon)
  - 変更量は1ページあたり1〜6片。12ページ全件が機械検査を一発で通り、差し戻しはゼロ
  - 採用後のページへ再実行すると変更0片。直し終えた文は触らない
